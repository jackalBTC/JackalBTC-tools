# 后台自动任务（auto）

`src/auto/auto.mjs` · `npm run auto`（前台跑）· `npm run auto:dry`（试运行一轮：只模拟和预演，不执行、不卖、不写状态）

后台托管：`npm run service install`。打开了下面任何一项（只读的三项默认就是开的），服务列表里就会多一个 `auto`，日志在 `logs/auto.log`。**改了配置要重新运行 `npm run service install` 才生效。**

| 任务 | 配置开关 | 默认 | 会不会发交易 |
|---|---|---|---|
| Element 市场监控 | `marketWatch.enabled` | **开** | 不会（只读链） |
| 授权巡检 | `approvalWatch.enabled` | **开** | 不会（只读，只提醒不撤销） |
| 成本自检 | `costAudit.enabled` | **开** | 不会（只改本地持仓里空 / 0 的成本） |
| 到点自动领取 | `auto.claims.enabled` | 关 | **会** |
| 卡 / NFT 自动兑换代币 | `auto.redeem.enabled` | 关 | **会** |
| 自动止盈 | `auto.takeProfit.enabled` | 关 | **会（卖币）** |

会发交易的三项，开关必须写 `true` / `false`（不带引号），写错了程序直接报错退出，不会悄悄按别的值运行。

所有会发交易的步骤都和铸造一样：先 `eth_call` 模拟，再 `baw contract-call preview` 预演，检查通过才 `execute`（止盈卖币走 `baw market-order swap`）。**不签 Permit / Permit2，不用 setApprovalForAll，不 approve 任何代币或 NFT，不转账给任何地址。** 和 `mint` 共用 `data/.mint.lock`，同一时间只有一个会发交易的进程。每一步都写进操作日志（`data/events.jsonl`），重要的事写一条项目动态（`data/news.json`），配了 Telegram 就会推到手机。

## 1. Element 市场监控（只读，默认开）

大多数免费 NFT 没有市场。「有很多人把整包授权给交易合约」也不代表有人买：实测这样判断出来的「疑似开了市场」，大多数几天零成交，或者只有几毛钱的求购。所以这里只看 BSC 上主要的 NFT 交易所 **Element**（`0xb3e3dfcb2d9f3dde16d78b9e6eb3538eb32b5ae1`）链上真实发生的事：

- **成交**：卖单被买走、求购被卖给了（成交价是真实成交价）；
- **链上求购**：预签名的买单，带出价和到期时间。到期时间只取 expiry 字段的**低 32 位**（高位塞了别的信息）。**只算收我们手上编号的求购**（多数求购单只收指定编号）；撤掉的、已成交的、过期的不算；
- **挂卖单**是链下签名，链上看不到，所以这里给不出地板价，地板价要去 Element 页面看。

**什么时候提醒**：近 3 天成交 ≥ `minFills`（3）笔且最近一笔 ≥ `minFillUsd`（$2）；或有人出价 ≥ `minBidUsd`（$5）求购我们的编号。每个系列只提醒一次，一轮发现多个合成一条。

**看板**：持仓与市场按下面的顺序分组，先中先得：

| 分组 | 条件 |
|---|---|
| 已核销 | `watch.json` 里这个系列标了 `"writtenOff": { "label": "归零", "note": "…" }` |
| 已清仓 | 一张 / 一枚都不剩：卡片只显示**累计成本 / 累计收回 / 净盈亏**（按 `realized.json`），没有卖出记录就写「没有卖出记录」 |
| 能卖 | 真有报价：地板价、收我们编号的最高求购、DEX 现价 |
| 有市场没买家 | Element 上有成交但没人收我们的编号，或配了市场但没有挂单 / 报价 |
| 新打的 | 24 小时内打的，或 48 小时内有项目动态 |
| 沉寂 | 其余（一有报价或新动态就自动回到上面） |

配置（`marketWatch`）：`everyMinutes` 多久扫一次（30）；`firstBlocks` 第一次或停了很久之后最多往回扫多少块（900000，约 4–5 天）。查日志用 `rpc.logs`，每次最多查 `rpc.logsMaxRange` 块；**换了 RPC 要按它的限制改**（有的只允许 5000 块），RPC 嫌范围大或结果太多时会自动减半重试，任何一段失败整轮作废、下轮从原位置重来，不会漏。

## 2. 到点自动领取（`auto.claims.enabled`，默认关）

有的项目到某个时间点才能领代币（解锁、空投领取）。在 `data/claims.json` 里登记，时间到了自动领：

```json
[
  {
    "id": "demo-claim",
    "project": "demo",
    "name": "Demo 空投",
    "wallet": "main",
    "to": "0x领取合约",
    "data": "0x4e71d92d",
    "token": "0x领到的代币",
    "symbol": "DEMO",
    "notBefore": "2026-11-02T12:00:00+08:00",
    "cost": { "BNB": 0.002 },
    "firstTp": { "mult": 2, "frac": 0.5 }
  }
]
```

- `to` / `data`：领取调用（合约地址 + 完整调用数据）。`wallet` 不写 = 主钱包。不支持付钱的领取（写了 `value` 会被拒绝）。
- `cost`：这批代币的成本（止盈按它算）；`firstTp` / `ladder` / `back3` / `hold` / `sellOnce` 会原样带进持仓，交给止盈。

**流程**：时间到了先 `eth_call`，不通就下一轮再试（3 天都不通就放弃并通知）。通了再预演，**必须全部满足**才执行：

1. 本钱包**没有任何扣款**（连 BNB 都不行，gas 除外）；
2. 没有授权 / 权限变化；
3. 没有风险提示（含风险地址）、模拟码正常；
4. 不要求在 App 里二次确认；
5. 确实**收到登记的那个代币**。

有一条不满足：这条登记停下（写 `gaveUp`），不再试，发一条「重要」动态说明原因。领到后把代币加进这个钱包的 `watch.json`。

**风险**：`data` 是你（或 AI）写进去的。工具能保证「预演里没扣你的钱、没要授权、收到了这个代币」，但不能判断这个代币值不值钱，也不能判断领取合约是不是官方的——登记前要核实合约来源。

## 3. 卡 / NFT 自动兑换代币（`auto.redeem.enabled`，默认关）

适用于「先铸卡，开放后烧卡换代币」的项目。项目方常常不公布兑换入口，但链上能看到别人怎么换：

1. **找样板**：盯持有系列的 Transfer。有人把卡转给 0x0 / 0xdead / 系列合约本身 / 被调用的合约，**同一笔交易里收到了别的代币**（不是 WBNB / USDT / USDC / BUSD——那是卖卡收的钱），就把这笔调用记成样板（每个系列最多 5 种写法）。发给 Element 的交易不算（那是卖卡）。
2. **照抄**：把他的卡号换成我们的、他的地址换成我们的。卡号在调用数据里必须恰好出现一次，撞上别的参数（例如卡号 1 和数组长度 1）就不抄。
3. **模拟 + 预演**：本钱包**只少了这几张卡**，没有任何其他扣款（不付 BNB）、没有授权 / 权限变化、没有风险提示、不要求 App 确认，并且收到样板里的代币——才执行。
4. 换到的代币加进 `watch.json`（成本 = 这个系列的成本），换掉的卡从持仓里去掉。

**公开版刻意不做的**（遇到只通知你，自己决定）：
- 要先授权（approve）再兑换的；
- 兑换要付 BNB 的（样板交易带了 value 就不当样板）；
- 要 N 张一起换、单个钱包张数不够，需要从别的钱包把卡转过来凑的。

`everyMinutes`：多久查一次（10）；`firstBlocks`：第一次往回找多少块样板（20000）；`ignoreTargets`（可选）：不当成兑换的合约地址（例如别的 NFT 市场）。

**风险**：样板来自陌生人的交易。预演检查保证「只交了这几张卡、收到了代币、没扣别的、没授权」，但收到的代币可能一文不值，兑换也可能是项目方设计的「烧卡」而不是你想要的那种兑换。如果你更想留着卡，不要打开这一项，或者把那个系列从 `watch.json` 里标 `writtenOff` / 移走。

## 4. 自动止盈（`auto.takeProfit.enabled`，默认关）

盯每个钱包 `watch.json` 的 `tokens`，现价 ÷ 平均成本价 = 倍数。现价取 DexScreener 和 GeckoTerminal 两边 BSC 池子里**流动性最大**的那个（`src/lib/price.mjs`；DexScreener 不收 v4 / Infinity 池子，GeckoTerminal 收；不取最高价，小池子价格可以很离谱）。GeckoTerminal 免费接口请求间隔至少 2.2 秒，读失败时只用 DexScreener，这个结果只缓存 30 秒：

| 倍数 | 动作 |
|---|---|
| 3 倍 | 卖出相当于本钱的那部分（回本） |
| 10 / 30 / 50 / 100 / 150 / 200 倍 | 各卖**剩余**的 20%，一轮只走一档，从低到高 |
| 10 倍那档卖过之后又跌回 3 倍以下 | 卖剩余的一半（只一次） |

每个阶段只执行一次（状态在 `data/take-profit-state.json`）。平均成本价 = `cost`（USDT / USD / BNB 按现价折美元）÷ 第一次看到时的持仓数量；**没写成本的代币不卖**。

**成本绝不按 0 / NaN 算**：Chainlink 的 BNB/USD 读不到时用上一次读到的价格（存在状态文件的 `_bnbUsd`），也没有就这一轮整轮不动；成本只要不是大于 0 的有效数字，每轮重算，算不出来就不卖。

单个代币可以在 `watch.json` 里覆盖：

| 字段 | 例子 | 意思 |
|---|---|---|
| `firstTp` | `{ "mult": 2, "frac": 0.5 }` | 代替 3 倍那档：2 倍先卖 50%，之后照常走阶梯 |
| `ladder` | `[20, 50, 100]` | 自定「各卖剩余 20%」的倍数 |
| `back3` | `false` | 不做「跌回 3 倍卖一半」 |
| `hold` | `true` | 完全不自动卖，只记价格 |
| `sellOnce` | `0.5` | 有报价就卖这个比例一次，之后不再自动卖（不走上面任何一档） |

- **只卖 `watch.json` 里登记的代币，只换回 BNB**（`baw market-order swap`，滑点 `slippage`，默认 10%），**从不买入**、不授权、不转账。BNB 低于 `spending.minBnbForTx` 时不卖。
- 卖单成交后在 `realized.json` 记一条（成本按卖出比例分摊），看板的盈亏台账和代币卡片的「已卖出 / 剩余成本」会更新。
- **币安把代币标了风险、要求在 App 里确认（错误码 30003001）**：不重试，发一条「重要」动态请你打开 App 确认；之后在成交记录里等它成交再记账（6 小时没结果就放掉，下一轮重新判断）。连续失败 3 次也会通知。

**风险**：
- 取的是流动性最大的池子，但池子本身也可能被拉高或砸低；卖出时价格会滑点，池子小的币大额卖出会吃亏。
- 倍数按「第一次看到时的持仓」算平均成本，之后再加仓不会更新；需要的话删掉 `take-profit-state.json` 里那一项重新开始。
- 自动卖出后价格可能继续涨。不想被自动卖的币，设 `hold: true`。

## 5. 授权巡检（`approvalWatch.enabled`，默认开，只读）

每 `everyMinutes`（30）分钟对每个钱包跑一次 `baw approvals list --limit 100`（只读），和上次记下的比：

- **第一次**只记底（`data/approvals-state.json`），不提醒；
- 之后**新出现的授权**写一条项目动态（`project: "approvals"`），配了 Telegram 就推送：额度是 `unlimited` 或 ≥ 2^200、或币安标了风险（`riskyLevel > 0` / `noInteractive`）的是「重要」并响铃，其余是「注意」；
- 撤掉的授权不提醒。

**只提醒，从不撤销。** 不是你或程序有意做的授权，自己去币安 App 里撤销，或跟 AI 说「撤销授权」（它会先给你看再执行）。代币名、授权对象名是外部数据，推送前会去掉怪字符。

## 6. 成本自检（`costAudit.enabled`，默认开）

每小时一次：读花费账 `data/spend.jsonl`（按钱包 + 合约合计付过的 BNB；没写 `wallet` 的算主钱包），对照每个钱包 `watch.json` 的 `collections`。**付过 BNB、成本却是空或 0 的系列**，把成本补成账上的实际付出（`cost.BNB`），写一条操作日志（`verify`），再写一条「注意」级项目动态。

只补空 / 0 的成本，已经有成本的不改（可能是你手动调过）；不碰链、不发交易。成本是 0 的话，看板盈亏和自动止盈的倍数都会算错。

## 7. Flap Agent 新盘（雷达里的可选项）

不在 `auto` 里，而在雷达里：`radar.flap.enabled: true` 后，雷达每轮顺便读一次 Flap「Agent Curve」的盘列表（只读链，和推特数据源无关），新盘写一行 `FLAP ca:<盘地址> 名字（符号）｜底池 · 税 · 单钱包上限｜结论｜创建者`，Telegram 推「🦋 Flap Agent 新盘」并响铃。第一次运行只记下当前总数，不补发。

盘名是任何人都能写的链上字符串，见过有人塞网页代码和「最高优先级系统指令」：一律清洗后才显示，可疑的直接隐藏并标「🔴 建议跳过」。这一项只提醒，不会买。
