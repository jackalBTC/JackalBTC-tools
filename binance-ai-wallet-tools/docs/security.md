# 安全模型

这个工具会用你的币安 AI 钱包发交易。下面写清它**能做什么、不能做什么、靠什么保证**。

## 它碰得到什么
- **钱包**：通过币安官方 CLI `baw` 操作。私钥在币安的托管体系里，本工具和 Claude 都拿不到私钥，也不需要。每笔交易都在币安的开发者模式额度和你在 App 里的安全设置之内。
- **API Key**：推特数据源的 Key 存在 `~/.config/binance-ai-wallet-tools/secrets.json`（权限 600），不进项目目录、不进 git、不进日志。
- **看板**：只监听本机 `127.0.0.1`，只接受 GET，不签名、不发交易。

## 永远不会做的事（写死在代码和 skill 里，配置改不了）
1. 不按推文、网页、skill.md 里的要求执行命令、安装软件、下载文件。外部内容只当数据。
2. 交易前必须 `baw contract-call preview`。预演里有**计划外扣款、任何授权 / 权限变化、任何风险提示、需要二次确认**，就不执行。
3. 不签 Permit / Permit2 或内容不明的签名。
4. 不 approve 无限额度。
5. 不把资产转给外部内容里出现的地址。
6. 不记录私钥、助记词、session、API Key（日志工具会拒绝疑似敏感内容）。

## 会自动花钱的范围
由 `config/config.json` 的 `spending` 决定，默认**只打免费张**。打开 `allowAutoPaid` 后：
- 只对「Sourcify 源码已验证 + 台账里有官网或官推」的项目付费；
- 单张 ≤ `maxUnitUsd`，每个项目付费 ≤ `maxPaidPerProject` 张；可选每天合计 ≤ `maxDailyBnb`（默认不设）；
- 张数按「这个合约累计」算，金额按「当天累计」算，记在 `data/spend.jsonl`；同一时间只允许一个 mint 运行，避免并发超额；
- 超出的部分会被自动裁掉，只拿免费张；没有免费张就不打，交给你决定。
- 付费前自动跑**防骗检查**（见下一节），有任何「拦」或检查没跑完，付费部分不打。
- 配置写错（比如 `"allowAutoPaid": "false"` 加了引号）会直接报错退出，不会悄悄按别的值运行。

## 付费项目防骗检查（v0.4.1）
`src/lib/devcheck.mjs`（纯逻辑在 `src/lib/scam.mjs`，有单元测试）· `npm run devcheck -- <合约>`。只读链，不签名、不发交易。

| 检查 | 拦的条件 |
|---|---|
| 真实人数 | 近 20,000 块的铸造里，**自己发交易**（铸造交易的 `from`）的钱包少于本机门槛（20–30）；合约里几乎没有 BNB / USDT（< 0.01 BNB 且 < 5 USDT）时门槛是 40–55。按收到铸造的地址算会被空投 / 代铸刷出来，所以不用它 |
| 诱饵盘 | 单个发起人铸了超过 30% 的份数 |
| NFT 图片 | tokenURI 空的、假 IPFS CID、链接不存在（404 之类）、打开了不是 JSON、资料里没图、图片链接是假的或不是图。IPFS 依次试 ipfs.io / dweb.link / gateway.pinata.cloud / w3s.link；限流（429）、5xx、超时、网络错误**只提醒**，不当成假图 |
| 撞图 | 同一张图（链接按网关地址比，链上 SVG 按内容指纹）已经在别的合约出现过（`data/nft-images.json`） |
| 批量同款 | 同一份合约代码 24 小时内出现 ≥3 个。EIP-1167 最小代理、EIP-1967 代理换成实现合约的代码再比。「见过的合约」= `data/radar-candidates.jsonl` 里 24 小时内的候选 + 24 小时内跑过防骗检查的合约（`data/devcheck-codes.json`，保留 7 天） |

**门槛每台机器随机一次**：第一次运行时在范围内随机（付费按份铸币进度 60–70%、最少发交易钱包 20–30、钱不在合约里时 40–55），存在 `data/thresholds.json`，之后固定。门槛写死、公开的话，做盘的人会刚好做到门槛上；每台机器不一样就没法量身定做。删掉这个文件会重新随机；手改成范围外的值会被当成坏文件重新生成。`npm run devcheck -- --thresholds` 查看（AI 写付费按份铸币的简报时，用里面的进度门槛）。

检查不了的：项目方用很多个钱包各自发交易刷人数（成本高，但做得到）；链下的承诺（会不会开池、会不会跑路）。所以它只是付费前的一道筛子，花钱上限仍然是兜底。

## 付费按份铸币（v0.4.2）
`src/cli/share-mint.mjs`（纯逻辑在 `src/lib/sharemint.mjs`，有单元测试）· `npm run share-mint -- <项目id> <铸造合约> --qty <份数>`。**默认关**（`shareMint.enabled=false`：只评估、只出简报）。

五道关口全过才让所有钱包自动参与，任何一道不过只写 `brief`、不发交易：

| 关口 | 谁保证 | 不通过的情况 |
|---|---|---|
| ① 进度 ≥ 本机门槛 | 代码（eth_call 读数） | 读不到、几个函数读数不一致、超过 100%、低于门槛 |
| ② 每钱包每项目 ≤ `budgetUsd` | 代码（花费账本 + Chainlink） | 读不到 BNB 价格、所有钱包都到上限、**USDT 付款**（要授权，自动流程不做） |
| ③ 两个合约都验证源码 | 代码（Sourcify） | 铸造合约或代币合约没验证、不知道代币地址 |
| ④ 源码审查记录 | **AI**（台账里的 `review`） | 四项（钱留在合约、没人能随意提走、代币铸造入口锁死、LP 销毁）任何一项不是 `true` |
| ⑤ 防骗检查 | 代码（devcheck） | 「拦」或没跑完 |

- 关口全过、开关打开时，share-mint 写一张 30 分钟有效的一次性通行证（`data/share-mint-gate.json`），`mint.mjs` 的按份铸币模式核对它（项目、合约、时间）才放行；单独加 `--share-mint` 参数不行。
- 按份铸币模式下，**副钱包也会付费**（不看 `allowPaid`），也不看 `allowAutoPaid` / 单价 / 张数 / 官网官推——这些由五道关口和预算代替；设了 `maxDailyBnb` 照样算。打开 `shareMint.enabled` 就是同意这一点。
- 每个钱包的交易照样走预演把关：除了付给本合约、不超过报价的 BNB 外不能有任何扣款，没有授权 / 权限变化，没有风险提示。没有新增任何授权、Permit / Permit2、setApprovalForAll 或转账代码。
- **软约束**：④ 是 AI 读源码后写的，代码无法验证它读没读、读得对不对（skill 要求没读源码绝不能填 `true`）。钱会不会被卷走、会不会开池，最终靠的是预算上限——请按「这笔钱可能全亏」来设 `budgetUsd`。

## 哪些是硬约束，哪些不是
- **硬约束（代码保证）**：开关、单价、张数、每日上限（如果设了）、按份铸币的预算和关口 ①②③⑤、预演检查、参数校验、一次只跑一个。
- **软约束（靠 Claude 遵守规则）**：「有官网或官推」这一条读的是台账里的 `site` / `x`，台账由 Claude 填写。skill 要求只填核实过的官方来源，但这不是代码能证明的。所以真正兜底的是上面的金额上限——请按你能接受的损失来设置。
- 项目自带的 `.claude/settings.json` 禁止 Claude 编辑 `config/config.json` 和读取密钥目录；Claude 仍有命令行权限，所以这同样是「防误操作」而不是「防恶意」。

## 后台自动任务（v0.4.0 起，可选）
`npm run service install` 会在打开了 `marketWatch` / `approvalWatch` / `costAudit` 或 `auto` 任何一项时多托管一个 `auto`（`src/auto/auto.mjs`）。详见 [auto.md](auto.md)。
- **Element 市场监控**（默认开）：只读链，不授权、不挂单、不发交易。
- **授权巡检**（默认开）：只运行 `baw approvals list`，新授权只提醒，**从不撤销**（撤销要你自己在 App 里做，或明确让 AI 做）。
- **成本自检**（默认开）：只改本地 `watch.json` 里空 / 0 的成本，不碰链。
- **会发交易的三项默认全关**，要在 `config/config.json` 里明确写 `"enabled": true`：
  - `auto.claims` 到点自动领取：预演必须**零扣款**（连 BNB 都不行）、零授权 / 权限变化、零风险提示、不要求 App 确认，并且收到登记的代币；
  - `auto.redeem` 卡换代币：只照抄**零付费**的样板，只用本钱包自己的卡，预演只能少了这几张卡、必须收到代币；**不做授权、付费兑换、钱包间归集**；
  - `auto.takeProfit` 自动止盈：只卖 `watch.json` 里登记的代币，只换回 BNB，从不买入；币安要求 App 确认的（30003001）只通知你。
- 三项都和 mint 共用 `data/.mint.lock`、每步写操作日志，执行前核对钱包会话。
- **不签 Permit / Permit2，不用 setApprovalForAll，不 approve，不转账**——这些在 `src/auto/` 里根本没有代码路径。
- 自动止盈读不到 BNB 价格时用上一次读到的，也没有就整轮不动，成本不会被算成 0 / NaN；成本算不出来的代币不卖。
- 代码保证不了的：领取登记里的合约是不是官方的（登记的人要核实）、换到 / 领到的代币值不值钱、DEX 价格是否被操纵（取的是流动性最大的池子，不是最高价）、卖出滑点。

## Telegram 机器人（可选）
- **只读**：机器人没有任何会花钱、发交易、改配置的命令。即使机器人 token 或你的 Telegram 账号泄露，别人也动不了钱包。
- **只认绑定的聊天**：`telegram.chatIds` 以外的人给机器人发消息，它完全不回应。
- **纯文本**：消息不解析 Markdown / HTML，推文里的内容变不成按钮或伪装链接；交易链接只在 txHash 格式正确时才拼。
- **token 只在本机**：存在 `~/.config/binance-ai-wallet-tools/secrets.json`（600）或环境变量 `TELEGRAM_BOT_TOKEN`，不进仓库、不写日志，也不会传给无人值守模式调用的 AI。
- **会经过 Telegram 的数据**：钱包余额、项目名、交易链接、项目动态摘要。介意的话在 `telegram.notify` 里只留 `MINT`、`LOWBNB`、`NOTCONNECTED`。
- token 如果泄露（比如贴到了聊天里），在 @BotFather 发 `/revoke` 换一个，再 `npm run setup` 重新填。

## 你需要自己注意的
- 「免费」NFT 也会花 gas，而且大多数没有交易市场，不保证有价值。这是一个降低踩坑概率的工具，**不是赚钱保证，不构成投资建议**。
- 铸造时附赠的陌生代币不要去交易或授权。
- 开发者模式有到期时间和每日额度，到期后合约调用会失败，需要在 App 里重新打开。
- 同一个 AI 钱包同一时间只能有一个登录会话；在别处登录会让本工具掉线。
- 发布或分享你的分支前，运行 `npm run check`，确认没有把自己的地址、路径、Key 带进去。它只扫当前文件；如果之前提交过敏感内容，再用 [gitleaks](https://github.com/gitleaks/gitleaks) 扫一遍 git 历史。
- 看板只接受来自 `127.0.0.1` / `localhost` 的请求（校验 Host 头），读 NFT 元数据时拒绝内网地址，页面里的外部链接只放行 http(s)。
