# 按机制选研究路径

（方法参考开源项目 EZbot Grok Scout，按「会自动执行」的场景改写。）关键词只帮你想到该查什么，不证明项目真用了这种机制；一个项目可能同时命中多行。

| 机制 | 要查清什么 | 容易误判 |
|---|---|---|
| Agent ID 资格 | 合约里实际检查的是调用者、收件人还是 handle；读注册表 `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F` | 持有 Agent ID ≠ 还有免费额度 |
| 直接 NFT 铸造 | 目标合约、完整方法签名、门槛、数量、价格、供应、收件人 | 有 mint 函数 ≠ 公众可调用；同文件可能有别的 mint |
| 白名单 / 签名领取 | 公开 / Merkle / 签名 / 持有门槛；凭证怎么拿、绑定谁、有效期 | 不自己造 proof，不签来路不明的消息 |
| 付费 / 授权 | 原生币还是 ERC20 付款、单位、spender、跨档价格 | value=0 也可能扣 ERC20；报价读失败 ≠ 0 价 |
| 身份 / 钱包额度 | 按地址、身份还是 tokenId 计数；转走后额度会不会恢复 | 「余额上限」≠「终身只能铸 N 次」 |
| 数量 / 附赠 | 付费数量、实际产物数量、赠品分开 | 返利 / 积分 ≠ 多铸了 NFT |
| 动态报价 / 随机 | 预言机报价的精度和时效、随机回调、reveal | 请求被受理 ≠ 产物到手 |
| 挑战 / 解题 | 题目版本与难度、截止、失败费、是否占名额 | 难题版本可能根本解不出；失败不扣费但会占名额 |
| PoW 挖矿 | 难度、全网算力（成功次数×难度反推）、过期规则 | 不在本机长时间跑挖矿；先算清期望耗时 |
| 合成 / 质押 / 产出 | 投入什么、是否销毁或锁定、产物何时可领、能否转让 | 增加权重 ≠ 拿到可交易资产 |
| 发射台 / 内盘 | 平台、曲线、计价币、迁移阶段、能否卖出 | 卖得出要实测报价；计价币可能不是 BNB |
| 募资 / 退款 | 资金托管在哪、退款条件、谁有权限 | 有 refund 函数 ≠ 现在能全额退 |
| 多阶段消耗 | 每一步的前置、等待、消耗、追加费用、完成条件 | 第一步成功 ≠ 整个活动完成 |
| 代币铸造 | 是增发、库存转账还是按池价买入；单位换算 | 首页宣传数字可能只适用早期阶段，必须对照白皮书和合约 |

遇到表里没有的机制：从原始资料讲清「输入什么 → 满足什么条件 → 状态怎么变 → 得到什么」，再决定该查什么。
