# 证据分层、费用与风险判断

（方法参考开源项目 EZbot Grok Scout，按「会自动执行」的场景改写。）

## 证据分四层，写结论时标清楚
| 层 | 例子 | 注意 |
|---|---|---|
| 项目方声明 | 官网、官推、白皮书、skill.md | 官网和官推是同一个发布方，**不算两份独立验证** |
| 代码规则 | 合约源码、eth_call 读出的规则 | 源码验证只证明源码对应该部署，不证明宣传真实、也不等于安全 |
| 当前状态 | 某个时刻读到的价格、供应、暂停状态 | 写明读取时间（必要时区块号）；会变 |
| 推断 | 根据以上推出的判断 | 必须说明是推断 |

冲突时先确认是不是同一条链、同一阶段、同一入口、同一单位、同一时点；还冲突就两边都写，不挑乐观的那个。

## 费用
- 分别列：本金、Gas、服务费 / 请求费、前置持有、后续领取 / reveal 费用、资产消耗。写币种、单位、数量。
- **读取失败不能当成 0 价、false 或售罄。** 报价异常不当零价。
- 只看到宣传「免费」→ 写「项目方称免费，实际未核实」，不进入自动执行。
- 代码里零价但没读当前参数 → 不说「现在免费」。
- 多个入口分别算，不能用免费入口掩盖收费入口。
- 单笔别人成功的交易不证明所有地址、数量、阶段都能参与。

## 合约与权限
- 识别角色：发行入口、资产合约、支付币、注册表、代理与实现、收款方。不要拿页面上第一个地址就用。
- 代理合约：状态从代理读，代码看实现；读不到实现就写清缺口，不说「不可升级」。
- 权限分两问：**具备什么能力**（改价、暂停、黑名单、增发、升级、提款）和**当前由谁控制**。owner 为零地址不排除其他角色或外部控制器。
- 「蜜罐」「不能卖」「无限增发」这类断言要有实际路径或当前证据，不能凭函数名或第三方评分。

## 流动性（常见错误：只查了几个官方池就说「没有流动性」）
- 只说实际查过的范围：「官方登记的 N 个池里只有 1 个有少量余额」，不推出「全网无流动性」。
- 总量、池余额、买卖税、能否卖出分开核实；能否卖出以实际报价（`market-order quote`）为准。
- 项目方说「已入池 / 已锁仓」要核实际资产、余额、LP 去向和可提取条件。

## 生态关系
- 「属于币安 Agent ID 生态」要有依据：原帖明确说、官网规则写、或合约里真的检查 Agent ID 注册表。
- 普通 BSC 代币、名字带 AI、用 .ai 域名，都**不足以**证明。证据不足就标「待核实线索」，不当作已确认的生态项目推送。

## 合约迁移
- 同一项目换了新合约：保留新旧两个地址和迁移关系，核实官方来源和旧资产怎么处理；不直接覆盖旧地址，也不当成一个全新项目。
